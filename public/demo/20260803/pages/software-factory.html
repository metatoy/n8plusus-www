Overview

How one engineer ships 4 products across 6 repos: spec-first planning, persona-cast agent pods, model-tiered fan-out, screenshot/sim verification skills, and a measured ledger — humans own every gate. Everything below is bespoke tooling I designed and built, not off-the-shelf — the factory is the product behind the products.

What I built

An AI-native software factory that lets one engineer ship multiple products across separate repos with the discipline of a team: a spec-first planning system, custom orchestration and verification skills, deterministic multi-agent workflows, an economics ledger, a persistent memory system, and a private studio operating layer (Coach OS). Each capability is a reusable, purpose-built piece — invoked by name, composable, and human-gated.

The bespoke feature set

The factory is a library of custom capabilities I authored. Grouped by what they do:

Planning & orchestration

  • Spec-first planning (/metatoy-plan) — nothing executes until an approved written spec exists; a persona-casting step assigns the right expert "seats" to each plan.
  • Pod orchestration (/orchestrate) — before any fan-out, a "pod card" declares shape × model·effort, batching, the verify stage, a token budget, and the human gates — then executes.
  • Model-tiered fan-out — price-aware routing: a flagship model on the hard reasoning, a workhorse on the bulk, a cheap model on mechanical volume.
  • Deterministic multi-agent workflows — scripted pipelines that fan agents out and back (parallel/pipeline stages, adversarial verify, loop-until-done) with reproducible, cached runs.

Verification (proof before it lands)

  • Headless UI screenshotting — a Playwright harness that captures any web surface for before/after layout proof.
  • iOS simulator debug loop — boots a repro, drives it, screenshots, and A/B-isolates the suspect change instead of blind-patching.
  • Live-plugin HID drive — synthetic clicks + region capture to verify an accessibility-opaque Figma plugin panel in the real app.
  • App Store readiness gauntlet — a pre-submission pass that catches rejection-class mistakes before every release.
  • End-to-end change verification — exercises the affected flow and observes behavior, not just tests.

Release & operations

  • Release ritual (cut-release) — build-bump → verify → gauntlet → strip dev hooks → handoff, stopping at the human archive/TestFlight gate.
  • Session handoffs — a standard git-state / what-shipped / open-gates document generated at every close.
  • One-command deploys — a Coolify deploy skill with health-check confirmation.
  • Remote agent appliance — a Synology-hosted loop that runs event-driven studio tasks off my main machine.

Autonomous idle lanes

  • Autonomous mode (/away) — when I step away, idle capacity runs an Experiment Engine (isolated git-worktree sandboxes, never touching main) and a Proposal Engine (draft feature specs, never shipped code).
  • Council brainstorm — a multi-pod discovery/ideation funnel.
  • Knowledge engines — scaling research loops that build verified, deduplicated knowledge bases (e.g. a ratings/review-systems corpus).

Economics, memory & governance

  • Pod ledger + rollup — tokens and wall-time measured per pod, reported as a share of a work block, so cost is visible per unit of work.
  • Persistent file-based memory — durable facts, feedback, and project state with a standing hygiene protocol so the system doesn't rot.
  • Studio dashboard network — an artifact hub with scheduled daily refresh across every project.
  • Human gate at every risk edge — deploys, pushes, and spend always stop for a human; the spec is the source of truth.

How it works

Work starts as an approved spec, then agent pods execute it. Model-tiered fan-out routes cheaper models to bulk work and stronger models to the hard parts. Verification skills capture screenshots or run simulations to confirm a change before it lands, and a measured ledger tracks tokens and wall-time per pod. Humans own every gate. Sub-project: Coach OS — the studio's operating system

Coach OS is a bespoke /coach operating layer I built on top of the factory — a private "operating system for a solo studio" that binds three traditionally-fragmented domains into one cybernetic loop. It is not compiled code: the whole OS is a set of agent-executed workflow specs and persona briefs.

Three vectors

  • Executive ingestion — zero-friction daily data dumps and a focus firewall (/coach dump, /coach shield, /coach status) so the day's inputs get captured without derailing deep work.
  • Studio incubation — MVP velocity, validation, and ship/technical-debt tracking across the product portfolio (/coach ship, /coach debt).
  • Financial allocation — runway awareness and advisory 50/50 routing of surplus (/coach runway, /coach allocate, /coach advice).

Features

  • /coach command suite — setup · dump · shield · status · ship · debt · runway · allocate · advice, plus on-demand data connectors (mcp connect).
  • Autonomy layer — event hooks (on payment webhook, on repo sync) and a scheduled tick that surfaces what needs attention — but never auto-executes a gated action.
  • Privacy-by-design invariants — finance is read-live, never persisted (no balances or revenue figures written to disk); the system is advisory-only and never moves money; data connectors are default-disconnected and project-scoped, so one project's session can't reach another's data.
  • One north-star metric — contraction of the transitional-runway gap: buying back the founder's time over a defined roadmap.

Coach OS is the clearest expression of the thesis: the same agentic factory that ships products also runs the business around them — as a safe, gated, measurable system.

Results & impact

The model makes solo delivery across six active repos possible, with token spend and wall-time measured per pod. It is how I ship products in parallel without a team — and, via Coach OS, how I run the studio around them under the same gated, measurable discipline.

Talking points

  • Every capability here is bespoke — I designed and built the planning, orchestration, verification, and operating layers, not assembled a toolchain.
  • Spec-first planning: nothing executes until an approved spec exists.
  • Model-tiered fan-out that routes bulk work to cheaper models and hard problems to stronger ones.
  • Deterministic multi-agent workflows with adversarial verification — parallelism you can trust.
  • Economics are first-class: tokens and wall-time measured per pod, with a human gate at every step.
  • Coach OS proves the factory generalizes from building products to operating a studio — with privacy-by-design (finance never persisted, advisory-only, isolated connectors).
