01

The agentic process

Spec-first execution. A human-written plan decomposed the migration into 13 tasks; a dedicated agent persona (Dev_Migration_Frontend) executed them in small slices under a hard lift-and-shift rule: legacy code untouched.
Approval gates, not free rein. Every consequential choice paused for a ~3-minute human approval — 71 gated decisions in total. The human steered; the agent typed.
Self-verifying agent. Chrome DevTools (MCP) was made a hard prerequisite so the agent inspects the running UI itself — no copy-pasting browser state to the human.
Tests as the safety net. The legacy unit-test corpus was rebased in: 2,285+ tests with enforced coverage thresholds (97/96/92/91) — green after every fix.
02

Logging & auditability

Decision log (bf-17798-agent-decisions.csv): all 71 gates recorded with options considered, choice, risk level, and outcome — graded outcomes overwhelmingly “worked,” 2 revisited, 0 abandoned. Its recommend-default-next-time column is a training set for the next migration.
Time log (bf-17798-timelog.csv): human vs. agent hours recorded per slice — the source of every number on this page.
Living status board in the spec, with a codified rule: every slice rolls up to the board. Plus a route-by-route UX sweep log and a porting-gotchas README for the next team.
03

Key findings

Pioneering work — no prior art existed

Research confirmed no completed Tornado → Next.js migration at BuzzFeed. This project establishes the playbook, with 12 React+Tornado services as candidates to follow it (see §06).

One root cause unified three publish bugs

Two dropped config.yml settings (img_cdn_url, s3_bucket) — injected only as deploy-time env vars — explained the Instagram, YouTube, and Twitter publish failures in a single forward fix.

A regression class, not one-off bugs

Server-side Tornado redirect handlers don’t port automatically: one was caught and ported (extension deep links); two more were identified and queued from the same pattern.

Pre-existing observability gap surfaced

Failed YouTube/Twitter publishes write no transaction record — in production today, predating the migration. Editors see a bare “Failed.” Now documented and ticket-ready.

04

The reusable migration pattern

_migration_source/ strategy — legacy code stays in-tree as the agent’s porting reference; nothing is lost mid-flight.
Platform-native rollout — rig --deployment-type migration, then a ramp: 10% → 50% → 100% with 24–48h monitored soaks, prod on timed 48h test windows in between.
A transferable kit — the agent persona, decision defaults, platform reference, and migration README are service-agnostic: the next migration starts warm, not cold.
05

End result

Feature-complete Next.js app — SSR bootstrap state, SSO middleware, API-gateway proxy, imagebuilder proxy, static assets — behavior-matched to legacy.
Stage-validated beta — all primary routes, API writes, and imagebuilder verified on stage; full jest suite green (2,306 tests).
In production test windows now — first 48h window ran; every reported bug root-caused and fixed forward. Remaining: final QA soak, then the percentage ramp.
