What I was trying to solve

The problemWhat the ladder does about it
More ideas than judgment. AI made exploring ten directions cheap and choosing between them no easier. The failure mode is discovering at the pull request that the whole thing was pointed the wrong way. The rungs. Work climbs spec → drawings → a clickable throwaway → code. Each step is a cheaper place to be wrong than the next, and a person judges the direction at every one before the next is paid for. 13 of 14 wrong directions caught at or before the step where they were knowable · false-advance 7–14% across five clean runs, 27 seeds, 3 vessels · false-catch 7.7%, so good work is left alone
One funnel, for people and for agents. Both need somewhere to put an idea, and it has to be grounded in what the company, the team and the project already said they were for. Ungrounded, the cheapest thing to produce is work nobody asked for. The ANCHOR and its gate. One file says what this is for. Every idea is admitted against it — typed by a person or proposed by the feeder, same gate — and its constraints only tighten as they cascade down to a vessel and a run. 18 ideas through one door in a night · 12 pull requests opened · 0 merged by the system · $105.97 of a $250 cap
A known price and a predictable floor. Output that is sometimes excellent, sometimes wrong, and never the same price is not something a team can build on. A cost on every step. Each shows what it spent, a ceiling parks the work visibly instead of creeping, and a verifier re-runs the tests rather than taking the agent’s word. The rate at which a wrong direction slips past a gate is measured and published with its bounds. $7.23 from typed sentence to merged pull request, 8 files (#12) · 18 runs at under $6 each · ceiling $36 a run, and it parks rather than creeps

GitHub triage agent tutorial

rough cut, public

The two-phase triage agent rebuilt on stock GitHub, for free — Issues, Actions, labels, one Python script, one ruleset. No servers, no training infra, no bespoke stack. Taught as chapters you complete rather than read, with the test suite as the progress meter: a fresh clone runs green with one skip per unwritten chapter, and the skips tick down as you build.

The repo nhunsaker/github-triage-agent-tutorial github.com/nhunsaker/github-triage-agent-tutorial Honest about what is finished: the Copilot-seat layer is wired, not yet verified on a seat.
What it costs nothing, for eight of the ten layers Layers 0–5 and 8–9 run entirely free on a GitHub account: the rulebook, the Actions wiring, the evidence dossiers, and the flywheel. Layer 6 wants one API key and a few cents an issue; layer 7 wants a Copilot seat. The LLM is layer six on purpose — the tutorial shows how far the deterministic half gets you before anyone reaches for a model.
A green run triage #33524587364 Actions · the agent running on the platform’s own primitives Routing starts near 30%, and layer 3 is what makes it not-30%. It walls out around 80% — the wall is the point, and layer 8 is the flywheel that turns human corrections into the rules that move it.

The Nudge

concept, not public

A read-only agent that offered a turnkey pattern at the moment an editor was most likely to take it: detect → recommend → draft the wiring → validate over a read-only MCP → one human-gated write. Built in two days. The delivery system upstaged the payload, which is the part worth talking about.

The write-up The turnkey adoption section n8plusus.com/portfolio/image-publishing.html The flow as a diagram, plus the eligibility guardrails and the security gate that held it back — which was the right call.
Not public nothing to open, on purpose The original is BuzzFeed’s — its code, routes and ticket stay theirs, so there is nothing here to open. The triage tutorial above is the provenance-neutral rebuild of the neighbouring agent, which is why that one can be.

💡 Idea bank

Open questions, none of them built. The ones I would want to work on next.

  • Adoption at the moment of need. Inside a running system, can an agent notice a practice or a piece of business value that already exists elsewhere in the company, and offer it at the point where someone is most likely to take it?
  • A co-pilot that learns the person. People think, work and write code differently. Can an assistant learn one person’s way of working well enough to strengthen it, and fill the gaps where it is thin — rather than pulling everyone toward the same average?
  • The diagram, in motion. System diagrams work, and some people learn by watching rather than reading. Can an agent build a cheap animation that explains a system — the same walkthrough as the diagram, played rather than read?
  • Workflows that keep learning. A workflow is set up once and left alone. Can it be tuned from its own history at setup, and keep improving as the system around it changes?
  • Picture the result before building it. Change a token from white to blue today and nothing warns you that a button with a black background just lost its contrast — the agent has to build the project, boot a headless browser, take a screenshot and read it. Can it flag that before any of that happens?
  • Accessibility as a workflow, not an audit. Can it be checked as the work is made, so the web gets easier to use as a side effect of building it?
