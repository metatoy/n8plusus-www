1 · Idea

What existed, and why the rewrite nobody had time for became possible

PubHub is BuzzFeed's social-publishing platform: 100+ connected channels, 40+ editors, hundreds of posts a day across six networks and fifteen post types. I owned its frontend for eight-plus years as the domain expert. The UI service was a ~70k-line React app served by a decade-old Python/Tornado backend on the company PaaS. A multi-quarter manual rewrite had sat on the roadmap for years; the team never had the capacity to start it, and every new feature paid the old stack's tax.

The idea was not "use AI on the codebase." It was narrower: a behavior-matched Next.js port, one slice at a time, with the existing test suite as the contract, the running production app as the oracle, and me deciding only at the points where judgment was actually required. If that worked once, it would be a method, not a project.

What I personally did: set the goal and the constraints, wrote the plan, designed the agent loop and its gates, made the 71 decisions, and packaged the result as a blueprint. The agent did the typing.

2 · Design and prototype

Spec first, with a number on it; then one slice, side by side with production

I did not point an AI at the repo and hope. The design was a written spec: the goal (a behavior-matched port, not a redesign), the port mechanics for each legacy piece, the order of slices, and the rules for when the agent must stop. It broke into thirteen tasks against the team's sixty-one-hour estimate, so there was a clock to beat and a definition of done before any code moved.

The prototype was the first slice: scaffold, mount, SSO, then the API-gateway and image-builder proxies and SSR bootstrap state. Each migrated page rendered next to the production page and had to match. That was the proof the loop could work; everything after was repetition with gates.

3 · Design system

What the migration had to preserve, and why the app was ready for it

The port was behavior-matched, so the design system was a constraint, not a deliverable. PubHub's UI sat on Foundation UI, the toolkit I had implemented in 2020–2022 on a Bootstrap foundation after leading the team off the legacy internal framework; it had been the working standard for four years with no rewrite, delivered as versioned shared components. That is what made the migration tractable: the components were already a library the new stack could consume, so the agent ported pages and data flow, not the design. Every slice had to render the same components with the same tokens, which the side-by-side check enforced.

The cost that shaped the idea: shipping a shared-component change meant a version bump, a publish, and updating each consuming service just to test it. A migration that touched the design system would have multiplied that; keeping it fixed kept the loop simple.

4 · Code

The agent loop: ported one slice at a time, with a human at every consequential decision

The agent worked the plan in small slices: Tornado request handlers became Next.js server-side data fetching and catch-all routes, the Webpack build became the Next build, React/Redux and the styling layer came across, tests moved with them. It ran free on the typing and stopped at every consequential decision: a data-model shape, a proxy edge case, a behavior that did not match. 71 of those, each logged with the choice and the reason. It ran overnight; I decided in the morning.

The rules that made it safe

  • Chrome DevTools as a hard prerequisite: the agent inspected the running UI itself rather than asking me to eyeball it.
  • Full suite plus lint green on every commit, or the commit did not land.
  • Every wall became a written-down answer: a build quirk, a proxy edge case, an SSR gotcha, captured as a learning artifact so the next slice and the next system would not hit it again.
  • My job moved up a level: designing the loop, setting the gates, deciding at the blockers. About five human hours total.

5 · Validation

Trust came from the gates, not from the model

Before the port: the existing suite could not be trusted as a contract at 26% line coverage, so I fanned out worker agents to raise it first. Coverage went from 26% to 97% (the agents wrote about 2,081 tests; the suite grew from 184 to ~2,265) and that work surfaced four real latent bugs before a single page moved. Thresholds were then locked so coverage could not silently regress.

During the port: the full suite (~2,300 tests) plus lint had to be green on every commit; each migrated page was verified side by side against production; anything that did not match was a blocker, not a note. After the port: the whole app was validated on stage, behavior-matched, before it was merged. Nothing merged on the agent's word.

Two clocks: I tracked human hours and wall-clock hours separately against the sixty-one-hour estimate. About five human hours; the rest ran unattended. That distinction is the honest way to say "8%."

6 · Production

Merged, then turned into a pattern the next twelve services could reuse

Nine hundred files and seventy thousand lines, behavior-matched to the original and validated on stage, in about 8% of the estimated engineering time. Once PubHub was on the modern stack the team could iterate on core features agentically: a redesigned, personalized home page and new planner filter tools shipped on it.

I built it as a pattern, not a one-off. The agent persona, the decision defaults, and the library of written-down answers were generalized into a reusable blueprint, queued for about a dozen similar services when the July 2026 layoffs ended the run.

What this case does not claim

Honest limits

  • The blueprint was queued across twelve services, not yet applied to them, when the layoffs hit.
  • This was a behavior-matched port: the design system was preserved, not generated or changed, by the agent.
  • It was a one-person loop on one team; the adoption story for the migration is the blueprint, not a rollout across teams.
  • Diagrams on this page are illustrative and clean-room; internal code and tickets are not shown.

Sorb: Figma → semantic tokens → the running app, verified before merge (studio, solo)

Where I took the same loop after BuzzFeed, at the design seam.
