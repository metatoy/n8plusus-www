1 · Idea

What existed, and why the change had to happen

PubHub is BuzzFeed's social-publishing platform: 100+ connected channels, 40+ editors, hundreds of posts a day across six networks and fifteen post types. I owned its frontend for eight-plus years as the domain expert: a ~70k-line React app on a decade-old Python/Tornado backend, deployed through the company PaaS.

Three things were true at once. Designers handed off in Figma with no link to the code, so engineers re-implemented by eye. The internal style framework, Solid, was under-supported and every team re-solved the same UI problems. And the backend's age had put a multi-quarter manual rewrite on the roadmap that nobody had capacity to start.

What I personally changed, in one line: I made the running app the source of truth for design, moved the team onto a system that could carry that, and then used agents, with human gates, to do the rewrite nobody had time for.

2 · Design and prototype

Spec first, and preview through the real renderer

Two habits carried every step of this workflow. Spec first: before any build, a written plan with the goal, the slices, and a number on it. The migration started as thirteen tasks and a sixty-one-hour estimate before an agent touched a file. Preview real: the prototype is never a mockup of the thing; it is the thing, behind a flag.

The clearest example is Callout, the on-site promotions admin I built from an empty repo as lead author. The operator's live preview renders through the same shared-library component that serves readers, so what you see is what ships. As the tool matured we walked free-form options back into governed presets: a theme dropdown, auto-contrast computed as CSS variables, spacing and type taken from the design file, one editable element. Constrain by default; allow freedom only where breakage is acceptable.

Why it matters for an AI-native workflow: a preview that only approximates the real thing erodes trust, and generated UI amplifies that. Rendering through the production component is what later made "verify against the running app" possible for agents.

3 · Design system

Foundation UI: a system that held for four years, and the versioned library that made the migration possible

In 2020 I led PubHub off Solid onto Bootstrap with two other developers, then implemented Foundation UI, our product designer's redesign of the post-creation surfaces, as a reusable toolkit on that foundation. The design was hers; the foundation choice and the build were mine. It stayed the team's working standard for the rest of the platform's life with no rewrite, and internal tools org-wide moved off the legacy framework because the replacement was visibly better to build on, not by decree.

Governance without a council

  • Kitchen-sink first: every component developed, tested, and merged on a kitchen-sink page before touching a real screen.
  • Feature-flag rollout, phased by platform: an eight-year-old production tool re-foundationed in flight.
  • The rubric written down: the team's design principles as the explicit review criteria, RFCs with comment periods for significant changes, and scaffolded components with tests, Storybook stories, and README by default, so peer review could carry quality.
  • Reach beyond the product: the Callout render unit, share components, and the feed subscribe button in the company React component library consumed by 79 projects.
The honest cost, and why it matters here: shipping a shared-component change meant a version bump, a publish, and updating each consuming service just to test it. Living that loop for years is why I later built Sorb (step 7). It is also why the migration could happen at all: the app was already on a library the new stack could consume.

4 · Code

The agent loop: ported one slice at a time, with a human at every consequential decision

The migration moved the ~70k-line Tornado UI service to Next.js. I did not point an AI at the repo and hope. I designed a loop: port one slice (handlers to server-side data fetching and routes, build, React/Redux, styling, tests), run the full suite on every commit, verify the new page side by side against production, and escalate to me only at a genuine blocker. The agent ran free on the typing and stopped at every consequential decision: 71 gated decisions, each logged.

What "AI-native" meant in practice

  • Chrome DevTools was a hard prerequisite so the agent inspected the running UI itself instead of asking me to eyeball it.
  • Every wall the agent hit (a build quirk, a proxy edge case, an SSR gotcha) became a written-down answer, so the next slice and the next system did not hit it again.
  • My job shifted to designing the loop, setting the gates, and deciding at the blockers. About five human hours; most of it ran overnight.

5 · Validation

Trust came from the gates, not from the model

Before the port, worker agents raised line coverage from 26% to 97%, which surfaced four real latent bugs, and thresholds were locked so coverage could not silently regress. During the port the full suite (~2,300 tests) plus lint had to be green on every commit, and each migrated page was checked against production before moving on. Nothing merged on the agent's word.

The same discipline ran the support-triage agent I spearheaded on the same team: a golden set of previously resolved tickets it had never seen, measured against known-good resolutions (84% handling accuracy), routing accuracy raised from 54% to the mid-70s on a locked holdout, a two-key fail-closed write policy so nothing auto-sends, and a human approving every action through a team-wide, month-long production beta. A negative result (a richer routing reference that raised routing but collapsed branch accuracy) was found and reverted rather than shipped.

And the user-facing validation that ran the whole time

  • A/B tests on shipped design: the redesigned share experience at +176% desktop / +82% mobile engagement, return visits via shared links 59% → 69%.
  • Six-month user-satisfaction health checks on the platform: 95% satisfied, 110 responses at peak.
  • react-axe accessibility audits in the pipeline; latency treated as a first-class metric (a channel-lookup redesign cut a hot path from 1,200ms to 25ms).

6 · Production

Merged, flagged, and turned into a pattern the next twelve systems could reuse

Nine hundred files and seventy thousand lines, behavior-matched to the original and validated on stage, in about 8% of the sixty-one-hour estimate. Post-migration the team could iterate on core features agentically on the modern stack: a redesigned, personalized home page and new planner tools shipped on it.

I built it as a pattern, not a one-off: the agent persona, the decision defaults, and the library of written-down answers were generalized into a reusable blueprint queued for about a dozen similar services. The triage agent reached its team-wide production beta on the same principle: autonomy expands only as the eval numbers earn it.

Adoption, honestly sized: Foundation UI was used by the R&R team (6 developers) plus about four other internal-tools teams and three designers; the company component library had 79 consumers; the triage beta ran team-wide for a month; the migration blueprint was queued across twelve systems when the July 2026 layoffs ended the run.

7 · Where I took the same loop next

Sorb: Figma → semantic tokens → the running app, verified before merge

Studio work, solo, and said as such. Sorb productizes the pattern above at the design seam: a designer edits a token in Figma, the plugin posts it to a bridge, and the React SDK applies it as CSS custom properties so the real components re-skin live before anyone merges. Tokens are modeled primitive → semantic → component (DTCG, Style Dictionary) and adapters carry one set into six UI frameworks. Every AI feature proposes, the live app confirms, a person merges; the first write feature, a contrast fixer, is judged by WCAG math rather than the model.

What was not finished

Honest limits

  • The Nudge recommendation system and the full triage rollout were in flight when the July 2026 layoffs hit; both were proven, neither fully rolled out.
  • Figma Code Connect was evaluated with our VP of Technology and design leadership, not shipped; it stops at Dev Mode, which is the gap Sorb was built to close.
  • Foundation UI was web-only React; cross-platform tokens are Sorb-era work, not BuzzFeed-era.
  • Sorb and the studio tooling are solo-scale; the team-scale adoption evidence is BuzzFeed's.
