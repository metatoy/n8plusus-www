Sorb MCP — feature reference

Sorb ships two Model Context Protocol servers so AI agents and MCP-capable IDEs (Claude Code, Cursor, Copilot) can read the real design-token truth from a design system — the resolved value of any token, the alias chain that produced it, and the components that bind it — and, on the paid tier, propose token changes as reviewable diffs and PRs. This page documents every shipped tool.

Overview @sorb/tap sorb mcp Hosted connect Roadmap

What Sorb's MCP does

A design system's "source of truth" usually lives in three disconnected places — Figma, the docs site, and the running code. Sorb resolves them into one queryable map: token → value → alias chain → the components that use it. The MCP servers expose that map to an LLM so it can answer "where does this button color actually come from?" with the resolved chain instead of a guess — and act on it safely.

Both speak the same conceptual vocabulary (list_tokens, get_token, resolve, and the component tools). Start with @sorb/tap for zero-setup read access; move to sorb mcp when you want live-app bindings and the write/preview/PR path.

1. @sorb/tap  read-only stdio

Point an agent at a design system and let it answer token questions — with the real alias chain and (when Sorb captures are present) the components that use each token. Three source modes: a bare DTCG token file (no Sorb account needed), a Sorb project's .sorb/ artifacts, or a running Sorb bridge. Tap: how agents draw from the tree.

Install

shell 
claude mcp add sorb-tap -- npx -y @sorb/tap --tokens tokens.json

Source flags: --tokens <file.json>… (bare DTCG) · --dir <project> (Sorb .sorb/ artifacts) · --bridge <url> [--pk <key>] (running bridge). With no flags it auto-detects .sorb/ in the cwd, else tokens/*.json. Works with any stdio MCP client; a LangChain example ships in examples/langchain-client/.

Tools 6

list_tokensread
List design tokens (id, CSS variable, resolved value, tier, type), with optional filters.
tieroptionalstring — filter by tier (component / semantic / primitive)
typeoptionalstring — filter by DTCG $type (color, dimension, …)
qoptionalstring — substring match over id / cssVar / value
Returns { count, tokens: [{ id, cssVar, value, tier, type }] }
get_tokenread
Get one token by id or CSS variable, including its raw authored value and alias chain.
idrequiredstring — dotted token id (e.g. component.button.bg) or its CSS var (--component-button-bg)
Returns { token } or { error }
resolve_tokenread
Resolve a token to its final value, showing the alias chain that produced it.
idrequiredstring — token id or CSS var
Returns { id, cssVar, value, chain, error? }
list_componentsread
List captured components / stories. Requires Sorb capture artifacts or a bridge.
No parameters.
Returns { count, components: [names] } — or a capability message in bare-DTCG mode
get_component_bindingsread
Show which tokens a captured component binds, by role (fill / stroke / cornerRadius / …).
componentrequiredstring — captured component name
Returns { component, bindings } · { capability } when captures absent
find_token_usageread
Reverse index — which captured components use a token, and on which roles.
idrequiredstring — token id or CSS var
Returns { id, count, usage: [{ component, roles }] }
Honest by design. The three component tools need Sorb captures or a bridge. In bare-DTCG mode they return a clear capability message instead of pretending the design system has no components.

Resource

sorb-tap://tokens  application/json

"Resolved design tokens" — the full resolved token map from the active source: { source, tokens }. Lets a client load the whole map as context in one read.

2. sorb mcp  read gated write stdio HTTP + SSE

The fuller engine, shipped as the sorb mcp subcommand of the @sorb/juice bridge CLI. It reads a running app's resolved tokens and its bound React components, and adds three proposal-only write tools for changing tokens safely. Runs locally over stdio, or hosted over streamable-HTTP with API-key auth and a Team-plan entitlement gate.

Install — local (stdio)

json · .mcp.json 
{
  "mcpServers": {
    "sorb": { "command": "sorb", "args": ["mcp", "--dir", "/path/to/your/app"] }
  }
}

Read tools work with zero write-config. Optional bridge + GitHub flags enable previews and PRs: --bridge <url>, --gh-owner / --gh-repo / --gh-pat. Hosted mode: sorb mcp --http [--port …] (needs DATABASE_URL) exposes /mcp + /mcp/sse.

Write tools 3 · gated · proposal-only

propose_token_changegated write
Compute the changeset + blast-radius for setting a token to a new value, and (with a bridge) open a live preview session. Does not apply the change.
idrequiredstring — token id
newValuerequiredstring — proposed value
Returns { change, blastRadius, preview, note }
rebind_componentgated write
Propose rebinding a component role to a different token id. Returns a binding-change proposal; does not apply (no network).
componentIdrequiredstring
rolerequiredstring — e.g. fill / stroke / cornerRadius
tokenIdrequiredstring — the token to bind to
Returns a rebind proposal + note
open_prgated write
Open a GitHub PR with a proposed token change (reuses Sorb's Open-PR flow). Requires GitHub credentials. Review + merge is the human step.
idrequiredstring — token id
newValuerequiredstring — proposed value
titleoptionalstring — PR title
Returns { prUrl, note } or { error }
Safety model. Write tools never auto-apply — they return diffs, blast-radius, live previews, or a PR for human review. Locally they're always available (they just need creds to reach GitHub); on the hosted endpoint they're gated (see below).

Hosted connect

The same sorb mcp engine runs as a multi-tenant HTTP service. Connect from the Sorb Cloud dashboard (Keys → MCP), which emits a copy-paste .mcp.json for the hosted endpoint.

json · .mcp.json 
{
  "mcpServers": {
    "sorb": {
      "type": "http",
      "url": "https://bridge.sorbcloud.com/mcp",
      "headers": { "Authorization": "Bearer <YOUR_SORB_API_KEY>" }
    }
  }
}

Transport

Streamable-HTTP at /mcp (primary) with an SSE fallback at /mcp/sse. Tenant scope (project / namespace) comes only from the authed session — never from tool input.

Auth & entitlement

Authorization: Bearer <key>. The 7 read tools are always free. The 3 write tools require a write-scoped secret key (sorb_sk_…) on a Team / Enterprise org. Read-only publishable keys (sorb_pk_…) → read_only; wrong plan → entitlement_required with an upgrade link.

Availability. The hosted MCP endpoint depends on the bridge MCP service being deployed and per-project token data wired up. The dashboard surfaces the connect snippet ahead of the endpoint being fully live — treat hosted mode as coming online, local sorb mcp and @sorb/tap as available today.

Roadmap

Specced/built on feature branches, not yet in the shipped tool list above:

sorb_verify_status

An 8th read tool: last-verified timestamp, drift state (token-hash delta) and changed-token count, so agents can warn when a design system has drifted from its captured snapshot.

Live-app reads

Tools that read tokens/bindings straight from a live sorb dev session rather than the on-disk .sorb/ snapshot.

AI explainer tools

Higher-level "explain this token / propose a reskin / check accessibility" tools layered on the resolved map.

Figma / Canopy edge

The Figma plugin can't be an MCP server (sandbox limits) — it's the producer edge that feeds captures into the sorb mcp pipeline the agents read.
